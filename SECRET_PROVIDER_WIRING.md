# Secret Provider Wiring

Production composition now requires an injected `SecretProvider` in addition to the managed persistence and observability boundaries.

The application validates production configuration through that provider. Required values are deployment-managed and are never generated by the application:

- `NEON_IDP_CLIENT_SECRET`
- `NEON_SESSION_SECRET`
- `NEON_DB_PEPPER`

The current `EnvironmentSecretProvider` is deliberately provider-neutral. A managed cloud secret-store adapter can replace it without changing the authentication service or composition contract.

Development and integration continue to use explicit local configuration paths. Production does not receive a secret fallback.

Apple configuration is outside this boundary and remains untouched.
